# aikadr — платформа ИИ-сериалов

Next.js + FastAPI + PostgreSQL + Nginx + Docker Compose. Сайт — `/`, студия — `/admin`.

## Запуск и почта

Полная инструкция VPS/HTTPS: [docs/DEPLOY.md](docs/DEPLOY.md). Бесплатная отправка кодов через Gmail и настройка своего SMTP: [docs/SMTP.md](docs/SMTP.md).

Локальная среда использует Mailpit: `docker compose up --build -d`. Сайт: http://localhost/, студия: http://localhost/admin, тестовые письма: http://localhost:8025. Mailpit не доставляет письма в реальные ящики. Новый сервер настраивается по `.env.example` с реальным SMTP и HTTPS; локальный `.env` нельзя переносить без изменения почтовых настроек.

Зритель регистрируется и входит с шестизначным кодом из письма. Автор, модератор и супер-администратор входят в `/admin` по email и паролю без кода. Восстановление пароля для всех требует письма. Код действует 10 минут, одноразовый, допускает 5 попыток, повторное письмо — через 60 секунд. В БД хранится HMAC кода, API и журналы код не раскрывают. Отправка ограничена по адресу и IP. Если SMTP недоступен, зритель не сможет пройти проверку кодом.

Демо-сериалы, тестовые ролики и пример тарифа больше не создаются. Опубликованный сериал виден посетителям только после добавления готового видео; до этого запись доступна в студии. Цены и реквизиты заполняет владелец.

## Роли и оформление

| Роль | Доступ |
| --- | --- |
| Зритель | Каталог, своя подписка и заявки на оплату |
| Автор | Свои сериалы, видео, просмотры и начисления |
| Модератор | Все сериалы и видео; без финансов, оплат и управления аккаунтами |
| Супер-администратор | Вся платформа, финансы, пользователи, оформление и тарифы |

Супер-администраторов может быть несколько. В «Пользователях» доступны создание, изменение роли и отключение аккаунтов. Собственный доступ к управлению отключить нельзя. Роль автора с материалами/начислениями сохраняется для отчётности; доступ можно отключить. Изменение роли или отключение отзывает прежние сеансы.

Ссылки на студию нет в публичном меню; авторам передавайте `/admin` напрямую. В студии есть выход и смена пароля. `ADMIN_PASSWORD` нужен только для создания первого владельца; последующие изменения пароля хранятся в PostgreSQL.

Владелец меняет логотип, фон главной, заголовок, описание, цвет и сезонную тему в «Оформлении». Подготовлена квадратная версия логотипа aikadr; сведения об ассете: [docs/BRANDING.md](docs/BRANDING.md). Интерфейс адаптируется под телефон, анимации учитывают настройку уменьшения движения.

## Оплата и доступ

Владелец в «Тарифах» заполняет общую инструкцию и добавляет один или несколько способов оплаты с реальными реквизитами. Способ можно отключить или удалить; старые заявки сохраняют его название. Зритель выбирает тариф и способ, самостоятельно переводит деньги и прикладывает чек (JPG/PNG/WebP, до 5 МБ). Владелец сверяет реальное поступление денег и подтверждает либо отклоняет заявку в «Оплатах». После подтверждения подписка активируется; при повторной покупке срок продлевается. Цена и срок фиксируются в заявке на момент создания. Данные банковских карт сайт не собирает. Скриншот сам по себе не доказывает оплату.

Telegram опционален: заполните `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `TELEGRAM_ADMIN_IDS` (ID администраторов через запятую), добавьте профиль `telegram` к запуску. Бот присылает чек и кнопки подтверждения/отклонения; проверяет и ID пользователя, и ID чата. Пока поля пусты, заявки обрабатываются в студии.

## Видео и просмотры

Автор создаёт сериал и эпизод, затем открывает «Загрузить видео» в отдельной вкладке. Там выбирает MP4/WebM до 2 ГБ и видит процент передачи, а после 100% — ожидание записи в БД. Страница сайта в другой вкладке работает независимо; вкладку загрузки нельзя закрывать до подтверждения. В «Пользователях» супер-администратор задаёт автору общий лимит в ГБ на видео всех его сериалов (по умолчанию 10 ГБ). API проверяет лимит с учётом замены прежнего файла и параллельных загрузок. Лимит нельзя снизить ниже уже занятого места.

Модель `videos` хранит имя, размер, формат, автора загрузки и связь с эпизодом. Содержимое файла — PostgreSQL Large Object, выдача — FastAPI `/api/videos/{episode_id}` с HTTP Range для перемотки. Файл читается частями, целиком в оперативную память не загружается. Доступ проверяется при каждом запросе. Внешняя ссылка допустима только для бесплатного эпизода.

В медиатеке можно удалить только файл, сохранив эпизод. Триггер БД освобождает Large Object при удалении, замене и каскадном удалении эпизода/сериала. Начисления сохраняются. Обложки и фоны лежат в volume `kadr_data`.

Засчитанный просмотр: зритель с активной подпиской смотрит эпизод не меньше 30 секунд; максимум один просмотр одной серии от одного аккаунта в сутки. Просмотры авторов и администрации не учитываются. События браузера можно подделать, поэтому для крупных оборотов потребуется отдельная антифрод-проверка. Автоматического перекодирования и HLS пока нет; готовьте совместимые MP4 H.264/AAC с `faststart` до загрузки.

## Распределение дохода

За календарный месяц UTC учитывается сумма подтверждённых в этом месяце заявок. Владелец может указать другую сумму для расчёта и долю авторов. По умолчанию авторам 80%, владельцу 20%.

`начисление автора = авторский фонд × просмотры автора / просмотры всех авторов за месяц`

Суммы округляются до целых сомов, остаток распределяется без потери денег. Если просмотров нет, фонд показывается как нераспределённый. Автор видит только свои показатели; владелец — всю ведомость. После окончания месяца он переводит деньги вне платформы и отмечает выплаты. После первой выплаты настройки расчёта месяца блокируются. Автоматических переводов и эквайринга нет.

## Эксплуатация и проверки

База находится в `pg_data`, изображения — в `kadr_data`. Резервная копия PostgreSQL должна включать видео: `pg_dump -Fc -b`. Проверяйте восстановление и храните копию отдельно от VPS. На диске 40 ГБ нужен запас под WAL, временные загрузки и резервные копии; позже файлы можно перенести в объектное хранилище.

Сборка: `npm run build` в `frontend`; Python: `python -m compileall backend/app`; конфигурация: `docker compose config --quiet`.

Интеграционный тест `backend/tests/test_smoke.py` требует отдельную пустую базу `kadr_test` и `TEST_DATABASE_URL`, заканчивающийся на `/kadr_test`. Проверяет коды, восстановление, отказ SMTP, права ролей, Range, освобождение файлов, оплаты, начисления и отзыв сеансов. `backend/tests/test_smtp.py` дополнительно проверяет реальную SMTP-доставку через локальный Mailpit; внешнюю почту он не отправляет.

`python -m app.clean_demo` в backend-контейнере удаляет только идентифицированные строки старого прототипа по известным ID, сохраняя авторский контент и записи с загруженными файлами/финансовыми связями. Скрипт не запускается автоматически.
