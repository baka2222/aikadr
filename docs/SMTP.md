# Письма с кодом: бесплатный старт

Зрителям код обязателен при регистрации, каждом новом входе и восстановлении пароля. Авторы, модераторы и супер-администраторы входят в `/admin` по email и паролю без кода. Восстановление пароля сотрудников по-прежнему требует письма. Действующий сеанс сохраняется до выхода, истечения срока или отзыва доступа.

В проекте собственная авторизация FastAPI + PostgreSQL. SMTP нужен только для доставки писем. До настройки настоящего отправителя письма доступны **только в локальном Mailpit**, публичная регистрация не готова к использованию.

## Вариант без своего домена: обычный Gmail

1. Создайте отдельный бесплатный Gmail-ящик для проекта или используйте свой. Придуманный адрес не подходит: нужен доступ к аккаунту отправителя.
2. В [безопасности Google](https://myaccount.google.com/security) включите двухэтапную аутентификацию.
3. Откройте [пароли приложений](https://myaccount.google.com/apppasswords), создайте пароль для `aikadr SMTP`. Скопируйте выданный пароль в `.env` без пробелов. Это отдельный пароль приложения, а не обычный пароль Google. Если пункт недоступен, проверьте ограничения аккаунта в [инструкции Google](https://support.google.com/mail/answer/185833?hl=ru).
4. На VPS заполните следующие поля `.env`, подставив **свой существующий адрес** вместо примера:

```dotenv
APP_ENV=production
SECURE_COOKIES=true
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_SECURITY=starttls
SMTP_USERNAME=your-project@gmail.com
SMTP_PASSWORD=your-16-character-app-password
SMTP_FROM=your-project@gmail.com
SMTP_FROM_NAME=aikadr
ADMIN_EMAIL=your-owner-mailbox@gmail.com
COMPOSE_PROFILES=
```

`SMTP_USERNAME` и `SMTP_FROM` для Gmail должны совпадать. `ADMIN_EMAIL` — логин владельца: при входе в студию письмо на него не отправляется. Для самостоятельного восстановления пароля владельца указывайте существующий ящик; он может совпадать с отправителем. Пароли не отправляйте в чат и не публикуйте в репозитории. Остальные секреты `.env` сохраните.

При обновлении старого проекта адрес единственного исходного `admin@kadr.local` заменится на указанный `ADMIN_EMAIL`, пароль останется прежним. Изменение `ADMIN_PASSWORD` не сбрасывает пароль уже созданного аккаунта. Если аккаунт уже использует другой реальный адрес, автоматической замены нет.

5. Настройте HTTPS по [DEPLOY.md](DEPLOY.md). После изменения `.env` пересоздайте контейнеры:

```bash
docker compose -f docker-compose.yml -f docker-compose.production.yml up --build -d
```

6. Откройте `https://ваш-домен/admin`, введите адрес владельца и пароль: код не требуется. Затем проверьте регистрацию обычного зрителя с другим своим ящиком и кодом из письма. Для самостоятельного восстановления пароля сотрудников указывайте им настоящие адреса.

Официальные [параметры Gmail SMTP](https://support.google.com/mail/answer/7104828?hl=ru): `smtp.gmail.com`, STARTTLS, порт 587, аутентификация отправителя. Включать POP для этого проекта не нужно.

У обычного Gmail есть [ограничения отправки](https://support.google.com/mail/answer/22839?hl=ru): при более чем 500 письмах за день отправка может временно блокироваться. Это верхний порог, а не обещанная пропускная способность; новый аккаунт и антиспам могут ограничить отправку раньше. Для небольшого старта вариант бесплатный, для растущей аудитории потребуется другой SMTP. Сервис входа при этом менять не придётся.

## Когда появится своя почта

Замените только `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURITY`, `SMTP_USERNAME`, `SMTP_PASSWORD`, `SMTP_FROM` и при необходимости `SMTP_FROM_NAME` на параметры провайдера. Для порта 465 обычно нужен `SMTP_SECURITY=ssl`, для 587 — `starttls`. Для своего домена добавьте SPF/DKIM/DMARC по инструкции почтового провайдера. Значения DNS зависят от провайдера, их нельзя выдумать заранее.

## Локальная проверка без внешних сервисов

Текущий локальный `.env` настроен так:

```dotenv
APP_ENV=development
SECURE_COOKIES=false
COMPOSE_PROFILES=dev-mail
SMTP_HOST=mailpit
SMTP_PORT=1025
SMTP_SECURITY=none
SMTP_USERNAME=
SMTP_PASSWORD=
SMTP_FROM=no-reply@aikadr.local
SMTP_FROM_NAME=aikadr
```

Запуск: `docker compose up --build -d`. Сайт: <http://localhost/>, студия: <http://localhost/admin>, письма для зрителей и восстановления пароля: <http://localhost:8025>. В студию входите с текущим логином администратора из `.env` и паролем, без кода. Mailpit перехватывает письма и **не отправляет их в Gmail или другие реальные ящики**.

Mailpit слушает только `127.0.0.1:8025`; не открывайте его для посетителей. При переносе на VPS замените локальные настройки на настоящие SMTP/HTTPS. Приложение в режиме `production` откажется запускаться с Mailpit, незаданным отправителем, незашифрованным SMTP или небезопасными cookies.

## Если письмо не пришло

- Проверьте «Спам», правильность адреса и лимит отправки. Код действует 10 минут; новый можно запросить через 60 секунд. После 5 неверных попыток нужен новый код.
- Ошибка 503 при отправке означает, что SMTP не принял письмо. Проверьте пароль приложения, совпадение Gmail-отправителя и логина, порт и TLS. При смене пароля Google старый пароль приложения может быть отозван.
- При сетевом тайм-ауте уточните у VPS-провайдера, разрешены ли исходящие соединения на порт 587. Не переключайте продакшен на незашифрованный SMTP.
- Если письмо принято SMTP, но задерживается у получателя, дождитесь его или запросите новый код. Пересылка делает предыдущий код недействительным.
- API не возвращает коды в ответах и не выводит их в логи. Настоящая доставка проверяется только после ввода ваших SMTP-данных.
